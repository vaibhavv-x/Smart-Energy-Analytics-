## 4. Questions faculty are likely to ask, and the weak spots

- **"Is this big data?"** 2.07 million rows, 126.8 MB: one HDFS block and two map tasks. The honest answer is that the workflow is the one a large cluster would use, not that the data is large.
- **"Is this a real cluster?"** Single node, replication factor 1. All daemons are real; there is no fault tolerance.
- **"Why do Hive queries take 20 to 90 seconds on small tables?"** The MapReduce engine starts YARN containers for every job (viva Q27).
- **"Why a French house from 2006 to 2010?"** It is a standard public benchmark with minute-level readings.
- **"How good is the forecast?"** It beats the naive baseline (MAE 3.82 against 4.50 kWh) but R² is only 0.48.
- **"Did you write this?"** The base is an MIT-licensed public repo, credited in the README, the dashboard and every doc. Our additions are listed in `FEATURES.md` under "What we added".

## 5. Known traps

- **Do not run `python scripts/run_pipeline.py` without the full dataset** in `data/raw/`. It falls back to the 5,000-row sample and overwrites `data/processed/`. Recover with `git checkout -- data forecasting hive dashboard screenshots`, then `bash run_on_mac.sh`.
- **The Mac's default Java is version 25.** Hadoop, Hive and PySpark need Java 11, which the script installs in `~/bigdata`. To run tools by hand, set the variables shown in `docs/installation.md`, section 4.
- **8 GB of RAM.** Hadoop, HiveServer2 and Spark together use most of it. Close other heavy apps, and stop the cluster when finished.
- **The Hive stage takes about 9 minutes** on every full run. To skip it, the earlier stages can be re-run and stopped with Ctrl+C once "10. Apache Hive" appears.
- **Folder name with a space.** The project sits in `big data`; Hadoop Streaming cannot take such a path, so the script copies the mappers and reducers to `~/bigdata/job` first.
